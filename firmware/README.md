# AI Passport 农场遥控器 — 烧录指南

> 硬件：FoloToy AI Passport（ESP32-C3 + ST7789P3 240×320 + 三键 ADC + USB Serial/JTAG）
> 功能：遥控拓竹农场 —— 下发任务 / 看状态 / 暂停恢复 / 暂停原因提醒

---

## 一、整个系统怎么跑起来（3 个部件）

```
┌──────────────┐   WiFi/TCP   ┌───────────────────┐   mTLS    ┌────────────────────┐
│  AI Passport │ ◄──────────► │  PC 桥接 bridge.js│ ◄────────► │ 农场服务器 8888    │
│  (本固件)    │  局域网 JSON │  (电脑上常驻运行)  │  HTTPS    │ (192.168.144.1)    │
└──────────────┘              └───────────────────┘           └────────────────────┘
                        USB 串口（插着时并行可用，也负责充电）
```

1. **电脑上**：双击 **`启动桥接.bat`** —— 不弹黑框，图标出现在**右下角托盘**
   - 右键图标：打开状态页 / 查看日志 / **开机自动启动**（勾选即生效）/ 重启桥接 / 退出
   - 桥接挂了会自动拉起来（每 10 秒自检）；日志在 `.tmp/bridge.log`
   - 命令行排错：`powershell -File server\tray.ps1 -NoTray`
2. **工牌上**：烧录本目录固件，连上本地 WiFi（`wesley`）
3. **拓竹农场管家客户端**（Bambu Farm Manager Client）必须保持运行 —— 桥接靠它提取 `x-bbl-sec-ts`

### 无线 vs 数据线

**不用插数据线也能用。** 桥接启动时会扫描本地网段（TCP 8897）找到工牌并认领连接：

```
[scan] 扫描 506 个地址找工牌 (TCP 8897)...
[scan] 发现工牌 10.10.1.148，认领连接
```

- 工牌在 8897 开 TCP 服务端，桥接**主动连过去**（PC 出站，不需要开防火墙入站规则）
- 插着 USB 时两条通道并存（USB 更快、不依赖网络）；拔掉后靠扫描自动接上
- 想强制只走无线：`node server/launch.js --nousb`
- 工牌每次连上会自报 `{t:hello,ip:10.10.1.148,mac:...}`，桥接据此认人

工牌**优先走 WiFi**（局域网 TCP），USB 线只用来充电——插着也能用，但**可以拔掉**。

- 工牌连本地 WiFi（`wesley`，WPA2-PSK），拿到 DHCP 地址
- 桥接每 3 秒 UDP 广播 `FARM?`，工牌回 `HERE:<ip>`
- 桥接主动 TCP 连 `<ip>:8897`（**PC 出站，不需要开防火墙入站规则**）
- 桥接从工牌的 USB 心跳里也能拿到它的 IP 作为兜底

串口和无线用的是**同一套 JSON 协议**，插不插线都能通信。

### 为什么工牌不能直接连服务器？（2026-10-25 实测结论）

试过三条路，结论是**读可以，写不行**：

| 服务器门禁 | ESP32 能否自己搞定 |
|---|---|
| TLS 1.2 + 客户端证书（CN=farm_client） | ✅ 能，证书和密钥才 5.5KB，server 接受 TLSv1.2 |
| JWT Bearer（7 天有效期） | ⚠️ 能塞进固件，但**换不到新的**：`/login/local/tokens` 要账号密码 |
| `x-bbl-sec-ts`（每个请求的令牌，约 1 小时） | ❌ **做不到** |

`x-bbl-sec-ts` 是整条链的根钥匙，实测差异：

```
GET  /captain              + 随机 sec-ts  → 200 OK      （只查存在性）
POST /task/:id/launchprinter + 随机 sec-ts → 400 invalid request
POST /task/:id/launchprinter + 真 sec-ts   → 200 业务响应
POST /login/local/tickets  + 真 sec-ts     → 400 "wrong user name or password"
POST /login/local/tickets  + 随机 sec-ts   → 400 invalid request
```

也就是说：**连登录都要 sec-ts**。而这个令牌是客户端本地用原生模块
（`electron_common_cuckoo` 的 AES-GCM，密钥派生函数 `deriveGcmKey` 在客户端和服务端都是加壳的）
现算出来的，1 小时级失效，ESP32 复现不了。

**所以桥接不是多此一举，它是替工牌去敲那扇门** —— 桥接从运行中的客户端内存里取现成的 sec-ts。
好处是客户端本来就得开着（你用它管农场），桥接挂在它旁边不额外增加负担。
已加入开机自启（窗口最小化），平时不用管。

## 二、烧录固件（两种方式）

### 无线升级（日常改固件用这个，不用插线）

只要工牌里已经是 **B1910 或更新**的固件，之后刷固件都可以无线完成：

1. 双击 **`启动桥接.bat`**（右下角出现图标，桥接在跑）
2. 双击 **`一键烧录.bat`**，问刷机方式时输入 **2** 回车
3. 工牌屏幕会显示「正在无线升级固件」+ 进度条，约 **1.5 分钟**完成并自动重启

也可以直接在命令行跑：`node tools/ota_wifi.js`

> **为什么不用标准 OTA 工具**：Windows 防火墙默认拦入站，标准 OTA 要"工牌回连电脑"，
> 回连会被挡掉（表现是 `No response from device`）。所以这里顺着已有的
> **电脑 → 桥接 → 工牌** 这条 PC 出站的链路把固件推下去，防火墙天然放行。

**无线刷机失败怎么办**（脚本会直接写原因）：

| 提示 | 原因与处理 |
|---|---|
| 桥接服务没在跑 | 先双击 `启动桥接.bat`，等右下角出图标 |
| 连不上工牌 | 看 `.tmp/bridge.log` 有没有 `[tcp] 已连上工牌`；工牌掉网会自己重连，等 10 秒再试 |
| 工牌拒绝开始升级 | 上一轮半途断了，再跑一次（脚本每次都会先 abort 清场） |
| 写入 N 字节处失败 | 信号弱或工牌忙，重跑即可，不会写坏（有超时自救） |

> **⚠️ 刷机通道选择 bug（已修，B1934 同期的桥接）**：桥接会误把"连到自己的回环 socket
> （`127.0.0.1`）"当成工牌，导致 OTA 抢错通道、报"无回应"。现象是 `.tmp/bridge.log` 里
> `wireless` 显示 `127.0.0.1`、且 `[ota]` 通道也是 `127.0.0.1`。
> 修复：`registerDeviceSocket` / `pickLiveSocket` / `otaChannel` 都拦掉回环地址，
> 工牌连不上 WiFi 时会自动退回 **USB 串口（COMx）** 刷。若仍卡住，重启桥接即可。

实在刷不进去就插一次 USB 线，`一键烧录.bat` 选 **1**（首次必须走这条）。

### 方式 A：一键烧录（推荐，约 5-10 分钟）

双击项目根目录的 **`一键烧录.bat`**。它会自动完成：

1. 下载 arduino-cli（约 5MB）
2. 安装 ESP32 开发板内核（约 300MB，首次慢）
3. 安装 TFT_eSPI / ArduinoJson 两个库，并自动把屏幕引脚配置（User_Setup.h）复制到位
4. 自动找到 AI Passport 的串口（Espressif USB 设备，VID_303A）
5. 编译并烧录

全程不用手动装 Arduino IDE。烧录成功后窗口会提示下一步。

> 如果自动找不到串口，脚本会提示你手动输入（设备管理器里看 "USB 串行设备 (COMxx)"）。
> 如果卡在 "Connecting..."：拔掉 USB，按住机身 OK 键不放再插上，看到进度后松手。

### 方式 B：Arduino IDE 手动烧录

### 1. 安装 Arduino IDE
去 <https://www.arduino.cc/en/software> 下载安装（选 Windows installer，一路下一步）。

### 2. 安装 ESP32-C3 开发板支持
Arduino IDE → 文件 → 首选项 → 设置 →  Additional boards manager URLs（引导板管理器地址）里加入：

```
https://espressif.com/package/esp32_index.json
```

（如果里面已有内容，点右边的框，新起一行加，不要覆盖。）

然后：工具 → 开发板 → 开发板管理器 → 搜 `esp32` → 安装 **esp32 by Espressif Systems**（版本 ≥ 2.0.0，建议装最新）。

### 3. 安装两个库
工具 → 管理库（Library Manager）：
- 搜 **TFT_eSPI**（作者 Bodmer）→ 安装
- 搜 **ArduinoJson**（作者 Benoit Blanchon）→ 安装 **v7.x**

### 4. 配置 TFT_eSPI 引脚 ★最容易卡住的一步★
把本目录下的 **`User_Setup.h`** 复制到：

```
C:\Users\你的用户名\Documents\Arduino\libraries\TFT_eSPI\User_Setup.h
```

**覆盖**原来的文件（先改名为 `User_Setup.h.bak` 备份）。不换这个文件屏幕不会亮，这是最常见的坑。

### 5. 打开并烧录
1. 用 USB 线把工牌连电脑（线要能传数据，别用纯充电线）
2. Arduino IDE → 文件 → 打开 → 选本目录的 `aipassport_farm.ino`
3. 工具菜单设置：
   - 开发板：**ESP32C3 Dev Module**
   - USB CDC On Boot：**Enabled**（必须！否则串口不通）
   - 端口：选新出现的那个 COM 口（设备管理器里显示 "USB 串行设备 (COMxx)"）
4. 点 **→**（上传）。等出现 `Hard resetting via RTS pin...` 就是成功了。

> **如果找不到 COM 口 / 上传失败**：大多数情况是缺驱动。去 <https://www.silabs.com/developer-tools/usb-to-uart-bridge-vcp-drivers> 装 CP210x 驱动，或者用 Windows 自动更新驱动（设备管理器 → 右键未知设备 → 更新驱动）。Espressif 原生的 USB Serial/JTAG 在 Win10/11 上一般是免驱的。
>
> **如果屏幕不亮**：90% 是第 4 步没做（User_Setup.h 没替换）。

## 四、工牌上的操作

工牌只有 3 个键（UP / DOWN / OK，在机身右侧，指甲轻按）：

| 按键 | 作用 |
|------|------|
| **UP / DOWN（短按）** | 首页在 7 个焦点间移动（4 张卡 + 事件/设置/全部设备）；列表页上下翻页 |
| **OK（短按）** | 进入 / 勾选 / 执行 |
| **OK（长按 1 秒）** | 一路退回总览（任何页面都能退） |
| **任意键（息屏时）** | 唤醒屏幕 |

> 短按是「按住 50ms 立即响应」，手感跟最初版本一致。

### 设置（首页 → 焦点移到「设置」→ OK）

```
设置
  自动息屏        10 分钟  ›     ← OK 进去改
  铃声与告警      已开启  ›     ← OK 进去：开关 + 单独试听
  立即息屏                      ← OK 立刻关屏
  ‹ 返回总览
  息屏后 WiFi 仍在线
  按任意键唤醒屏幕
```

### 铃声（设置 → 铃声与告警）

这一页就是用来**确认喇叭到底响不响**的，点一下就播：

```
铃声
  告警开关              已开启     ← OK 开/关
  音量  ▮▮▮▮▮(超大)      80%       ← OK 切档（40/60/80/100/超大），每档响一声
  成功音效              琶音 ›     ← OK 进去挑（4 选 1）
  故障音效              三连 ›     ← OK 进去挑（4 选 1）
  ‹ 返回设置
```

音量共有 **5 档**：`40% → 60% → 80% → 100% → 超大`。
- 普通 4 档是纯 DAC 增益（见下面 dB 表），离得近就把音量调小（比如 40%）避免吵；
- **「超大」档**专门给"离得远、环境吵、必须听得见"的场景：DAC 仍锁 0dB（不削顶），
  只在数字端用 tanh 软饱和再压约 +5dB 响度，失真温和（奇次谐波），不会破音。
- 第 5 格（超大）在界面上用警示色（橙红）标出，一眼能认。


**完成音效 4 选 1**（靠"几声 + 节奏"区分，音符数 3 / 2 / 4 / 7）：

| # | 名字 | 听感 |
|---|------|------|
| 1 | 琶音 | 叮—叮—咚，慢速三声上行 523/659/784Hz |
| 2 | 双音 | 高→低大跳两声：784Hz 短 + 523Hz 长 |
| 3 | 清脆 | 三声极短（80ms）+ 一声收尾，最干脆 |
| 4 | 欢快 | 659/784 来回抖三下 + 长收尾（7 声，最快） |

**故障音效 4 选 1**（音符数 6 / 2 / 10 / 3）：

| # | 名字 | 听感 |
|---|------|------|
| 1 | 三连 | 嘟-嘟-嘟 下行 784/784/587，来两轮（默认） |
| 2 | 长鸣 | 两声拖长的下行低音 587→494Hz（700/780ms） |
| 3 | 四短 | 急促四连击 + 一落，来两轮（10 声，最急） |
| 4 | 低沉 | 三声同音闷响，压到最低 440/440/392Hz |

> **⚠️ 音色只有"纯正弦"一种，别再加别的音色**：
> - **双音和弦**（f + 上方纯五度）→ 听着就是老式手机铃声，已废弃
> - **方波** → 谐波被这块小喇叭削平，和正弦听起来没区别
> - **平顶持续音**（不衰减）→ 老式手机的鸣笛声
>
> 现在的做法是**纯正弦 + 钟形包络**（8ms 起音、指数衰减到 45%(长音)/28%(短音)、10ms 收尾；超大档 70%/55%），
> 听着像"叮/咚"的钟声；区分不同音效**只能靠节奏和音高**。

> 电脑上可以先试听：`python tools/preview_tones.py`
> 会把这 8 个音原样合成成 wav 放到 `音效预览/`，双击就能听，
> 不用在工牌上一首首按。加音效时改 `tools/preview_tones.py` 和固件里的
> `playFinishTone/playFaultTone` 要同步。

- **试听不受开关限制**：就算把「告警开关」关了，试听照样会响
- **音量**：OK 循环切 40% → 60% → 80% → 100% → **超大**，**每切一档立刻响一声**
- 开关/音量/音效选择都**存 NVS**，掉电不丢
- **这里试听有声音、但真出事时不响** → 去看 `.tmp/bridge.log` 里的 `[evt]` / `[alarm]` 行（见下面排错）

**声音告警**（ES8311 编解码器 + 板载喇叭）：

| 场景 | 声音 | 触发条件 |
|------|------|----------|
| 打印完成 | 三声上行琶音「叮—叮—咚」（C5-E5-G5，523/659/784Hz） | 任一设备打印完成（kind=`finish`） |
| 异常 | 连续两轮「嘟-嘟-嘟」（下行音，784/784/587Hz） | 打印失败 / 暂停 / HMS 报警（kind=`fail` `pause` `hms`） |
| 试听 | 一声短音 | 音量切档 / 打开告警开关时响一下 |

> **频率是照着这块喇叭挑的**：板载小喇叭 1kHz 以上响应掉得很厉害，
> 最早用 988/1319Hz 做完成音，听起来几乎没声（不是音量问题，是频率太高）。
> 现在完成音和异常音都压在 **494~784Hz**，这块喇叭最响的区间。
> 改音效时别再往 1kHz 以上挑，也别往 494Hz 以下压（推不动，会破音）。

**⚠️ 事件行显示成拉丁字母乱码（如 `hms`/`new`/`launch`）**：
这是固件漏认了服务器下发的事件类型。服务器会发 `kind=pause/finish/resume/fail/state/hms/new/launch`，
旧版固件只认前几个，**不认识的 `kind` 会走兜底 `"%s %s"` 把原始英文 kind 直接印出来**
（小屏上 `hms` 的 s 又容易被看成 `y`，变成 `hym` 之类的乱码）。
修法（B1935）：补齐 `hms→异常` / `new→已上线` / `launch→任务下发` 的渲染，
并把兜底改成中文「通知」，**永不露原始英文**。新增中文（异/线/务/通/知/上/发/常）都在 GB2312 字库内，无需重做字库。
受影响的两处：首页「最近动态」和「事件记录」页都已同步改。

**⚠️ 音效合成必须用整数查表，不能在每个采样点调 sin()/powf()**

ESP32-C3 是 RV32IMC 内核，**没有硬件 FPU**，`float`/`double` 全部由软件模拟。
早期版本每个采样点都算一次 `double` 的 `sin()`，B1929 又加了 `double` 的 `powf()`，
16kHz 立体声下 CPU 被吃掉一半以上 → WiFi 一抢占，I2S DMA 直接欠载：

- 症状 = **断音「卡卡」+ 波形断续「沙哑」**，听起来像喇叭坏了
- 关键特征：**怎么调频率、换波形都没用**，因为问题根本不在音色上
- 现在的做法：256 点正弦表（启动时用 `sinf` 建一次）+ 32 位相位累加器 +
  定点(Q16)指数包络，热路径里只剩整数乘加

改音效时如果又开始「卡卡」，先检查是不是又引入浮点了。

- 做功放/喇叭那一路是常开的，不需要额外 GPIO 控制
- 告警响起时如果屏幕是黑的，会**先自动亮屏再响**
- 防吵：完成类最短间隔 3 秒，异常类最短间隔 20 秒
- 开关和音量都**存进 NVS**，掉电不丢
- `0x31` 的 bit5/6 是静音位，开机时明确清掉

**⚠️ ES8311 的 DAC 音量寄存器 `0x32` 是 dB 刻度，不是百分比！**

| 寄存器值 | 实际增益 |
|---|---|
| `0x00` | −95.5 dB（基本静音） |
| **`0xBF`** | **0 dB ← 干净的上限** |
| `0xC0` | +0.5 dB |
| `0xFF` | **+32 dB** |

每 1 LSB = 0.5 dB。**所以 `volume * 255 / 100` 这种写法是错的**：
80% → `0xCC` = **+6.5 dB**，直接削顶，听起来就是「沙哑、破音」；
100% → `0xFF` = **+32 dB**，彻底炸。

本工程用 `volToReg()` 按 dB 映射并**封顶 0 dB**：

| 档位 | 寄存器 | 增益 | 备注 |
|---|---|---|---|
| 40% | `0x9B` | −18 dB | 离得近用，最小声 |
| 60% | `0xA7` | −12 dB | |
| 80% | `0xB3` | −6 dB | 默认 |
| 100% | `0xBF` | 0 dB | 干净满档 |
| **超大** | `0xBF` | 0 dB + **数字 +5dB 软饱和** | DAC 不超 0dB，靠 tanh 在数字端再压响度，不失真破音 |

> 诊断口诀：**声音沙哑/破音，先查增益，别查音色。**
> 一个纯正弦波是不可能"沙哑"的，除非它被削顶了。

另外 `0x37` 是 DAC EQ 控制，官方默认 `0x08`（EQ 旁路）。写成 `0x48` 会打开 EQ，给声音染色。

#### 「该响没响」怎么查

工牌会把每个事件和每次判断都打到 USB 串口，桥接收进 `.tmp/bridge.log`：

```
[evt] kind=pause dev=xxx to=PAUSE      ← 事件有没有收到
[alarm] 响铃 异常 kind=pause            ← 决定要响
[alarm] 开关关闭，不响 kind=pause        ← 告警开关是关的
[alarm] 冷却中，不响 kind=pause          ← 20 秒冷却内，被合并掉了
[audio] 播告警 kind=1                   ← 真的在播
[audio] ES8311 已就绪                   ← 音频芯片起来了
```

对着这几行就能定位是**没收到事件** / **开关关着** / **被冷却合并** / **喇叭本身不响**。

自动息屏可选：**10 / 20 / 30 / 60 分钟**，或者「自定义」（1~120 分钟）：

```
自动息屏
  10 分钟      当前
  20 分钟      ›
  30 分钟      ›
  60 分钟      ›
  自定义 15 分钟  上下调     ← 选中按 OK 进入调节
  ‹ 返回设置
```

- 自定义档：OK 进入调节后 **UP/DOWN 改数值**（20 以下每次 ±1，20 以上每次 ±5），再按 OK 保存
- 设置**存进 NVS**，掉电/重启都不丢

### 省电（息屏）

- **无操作到设定时间自动息屏**（默认 10 分钟，可在「设置」里改）：背光关闭 + 屏幕清黑，
  WiFi/TCP 保持在线（远程下发任务照常可用）
- 设置页里「立即息屏」可手动关屏
- **按任意键** 唤醒
- 官方按键说明：按住电源键 0.5 秒开机 / 长按电源键 2 秒关机 —— 电源键是**硬件开关**（不在 GPIO 表里），
  固件改不了它的行为，所以息屏走「自动超时 + 设置页手动」这两条

**每个列表第一项都是「‹ 返回」，长按 OK 也能随时退回总览。**

### 首页（2×2 四张卡 + 最近动态 + 三个入口）

```
┌──────────────┬──────────────┐
│ 打印中        │ 空闲          │
│      3        │      30       │
│ 最快8分       │ 可下发        │

  A1-c1 暂停 热床温度异常
─────────────────────────────
  事件   │  设置  │  全部设备
```

- **四张卡是二级菜单入口**：上下键移动焦点（共 7 个位置：4 卡 + 3 入口），OK 进入
  - **打印中 / 空闲 / 异常** → 进该类设备的**详细列表，可翻页**（右侧有滚动条）
  - **队列** → 任务列表（可下发）
  - **事件 / 设置 / 全部设备** → 底部三个入口
- 「异常」= 暂停 + 打印失败 + 离线，卡上直接显示 `停N 障N`
- 右上角是**电池图标 + 电量**（板载 CW2017 电量计 I2C 0x63，按锂电放电曲线换算，低于 20% 变琥珀色）

- **设备列表**（分类后）：只显示该类机台，一屏 6 行，**上下键翻页**、右侧滚动条指示位置
  - 从首页卡片进来的已经是筛选过的分类列表；「全部设备」是完整列表
  - 选中按 OK 进详情：任务名、状态、进度、剩余时间、喷嘴/热床温度
  - 详情里的操作项（按状态自动出现）：
    - 打印中 → 「暂停打印」
    - 打印完/空闲 → **「清盘（清理打印盘）」** → 弹确认页「请确认打印件已取走并已清理打印盘 / 清理后该机台可接新任务」→ 确认后发 `opt: bed_clean`
    - 暂停中 → 「恢复打印」
- **任务**：排队任务列表（剩几件 + 已派几台）
- **事件**：哪台暂停了、为什么（HMS 原因）、哪台完成/失败

### 下发任务（完整流程）

```
任务 → 选中 → OK
   ↓ 选机台（多选，自动勾了第一台空闲机）
   下一步  已选1台 ›          ← 在顶部，按 DOWN 去挑更多
   ☑ A1-01  空闲             ← OK 勾选/取消
   ☐ A1-04  空闲
   ↓ 下一步
   ↓ 确认下发（3 行，上下键移动）
   料盘映射   外挂料盘  ›      ← OK 切换：外挂/AMS第1~4槽
   已选机台   A1-01
   确认下发                    ← OK 执行
   ↓ 结果
   A1-01  成功
   A1-02  失败  device is not assigned to task
```

- 只有「空闲/已完成」的机台能勾选，正在打印的显示「使用中」
- 勾完把焦点移到最上面的「下一步」按 OK 进确认页

### 打印设置（确认页第 3 项，独立一页）

```
打印设置
  自动调平            [ 开 ]     ← OK 切换
  流量校准            [ 开 ]
  延时摄影            [ 关 ]
  ‹ 返回确认页
默认：调平开 校准开 延时关
```

- 默认 **自动调平开 / 流量校准开 / 延时摄影关**
- 下发时随命令发给服务端：`print_option:{auto_bed_leveling, flow_dynamic_calibration, timelapse}`
- 服务端确认支持该字段（和 `ams_mapping2` 同属一个 launch item）
- **料盘映射决定实际用哪卷材料**：外挂料盘 = `ams_id 255`，AMS 第 N 槽 = `ams_id 0, slot_id N-1`
- 确认页会显示任务的打印设置：**自动调平 ✓ / 流量校准 ✓ / 延时摄影 ✗**
- **清盘（喷嘴清洗）在 API 里没有对应字段** —— 它是电脑端建任务时就定好的，
  工牌这侧只能显示不能改，确认页会明确提示
- 下发结果逐台显示，失败会带服务端给的原因

## 五、常见问题

**Q：工牌显示"正在连接 PC 桥接服务..."**
A：电脑上没跑 bridge.js，或者 USB 线松了。跑起来后按 OK 会重连。

**Q：事件里看不到暂停原因**
A：暂停原因来自打印机的 HMS 自检数据，部分老固件机型不上报，只能显示"未知原因"。

**Q：桥接报错 `no sec-ts candidates`**
A：拓竹农场管家客户端没运行。桥接需要从它内存里提取访问令牌，把它开着就行。

**Q：换电脑了怎么办**
A：credentials 里的证书是和农场配对的，换电脑需要重新从客户端内存提取（用服务器目录里的 sects.ps1 那套流程），或者直接找我要新的。

## 六、开发者备注

- 串口协议是 \n 分隔的 JSON，115200 波特率，见 .ino 顶部注释
- 桥接每 5 秒推一次全量状态（约 1.7KB），工牌 15 秒兜底请求一次
- 屏幕是 ST7789P3，**必须用厂商专属初始化序列**（已在 setup 里发全 13 条），通用库默认序列点不亮这块屏
- 三键是 GPIO0 电阻梯分压（UP≤150mV / DOWN≤447mV / OK≤1900mV，固件阈值取 250/1100/2500mV），不是三个独立 GPIO
- 串口对象用 `FARM_SERIAL` 兼容层：`CDCOnBoot=cdc` 时是 `Serial`，否则 `USBSerial`（内核 2.x 里 `Serial` 是 UART0=GPIO21 会撞背光）

### 烧录方式（手工排错用）

`arduino-cli --upload` 在这块板上会 **Write timeout**，必须直接调 esptool：

```
esptool --chip esp32c3 --port COM16 --baud 115200 \
  --before usb_reset --after hard_reset --no-stub write_flash -z \
  0x0 build\aipassport_farm.ino.bootloader.bin \
  0x8000 build\aipassport_farm.ino.partitions.bin \
  0xe000 <esp32内核>\tools\partitions\boot_app0.bin \
  0x10000 build\aipassport_farm.ino.bin
```

- `--before usb_reset`：C3 的 USB Serial/JTAG 只能这样进下载模式（DTR/RTS 无效）
- `--no-stub`：stub 在这块板读不到 flash（报 "Unable to verify flash chip connection"）
- 波特率用 115200，改 460800 会 "No serial data received"

### ★ TFT_eSPI 2.5.43 的 C3 bug（必须打补丁）

`TFT_eSPI/Processors/TFT_eSPI_ESP32_C3.h` 第 71 行原为 `#define SPI_PORT SPI2_HOST`，
而 C3 上 `SPI2_HOST = 1`，但 SDK 的 `REG_SPI_BASE(i)` 只在 `i == 2` 时返回 `DR_REG_SPI2_BASE`，
否则返回 **0** → `SPI_USER_REG` 算成 `0x10` → 写 0x10 触发
`Guru Meditation Error: Store access fault` 无限重启。

改成 `#define SPI_PORT 2` 即可。一键烧录.bat 会自动打这个补丁。
